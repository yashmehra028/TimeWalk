# CMS Inner Tracker (Phase-2) - SCurve Timing Alignment & Masking Toolkit

This repository contains a suite of Python-based tools designed to automate, optimize, and analyze injection delay SCurve scans for the characterization of the CROCv2 (RD53B) readout chips within the CMS Phase-2 Inner Tracker upgrade. 

The toolkit integrates directly with the **Ph2_ACF** data acquisition framework. It provides a pipeline to manipulate pixel masks and mathematically extract the optimal timing alignment for the analog front-end.

## Directory Structure & Setup

To ensure the integration with the Ph2_ACF middleware, the scripts must be placed in their respective target directories before execution:

*   `pythonUtils/pyUtilsIT/`
    *   `masker.py` (or your custom mask generator)
*   `rundir/` (or your active working directory containing the XML configs)
    *   `scurve_launch.py`
    *   `scurve_graph.py`
    *   `scurve_uniformity.py`
    *   `sensor_geometry.yaml`
---

## 1. Mask Generation & Manipulation

### `masker.py`
**Purpose:** Generates a text-based mask file defining which specific pixel coordinates should be enabled and injected during the calibration.
*   **Input:** Hardcoded loop logic (user-defined rows, columns, and steps).
*   **Output:** `my_mask.txt` (A list formatted as `row X col Y en` and `row X col Y inj`).
*   **Methodology:** Uses Python `set()` structures to prevent duplicate coordinate entries and systematically writes the Ph2_ACF-compliant masking syntax.
*   **Usage:** Run this directly in the terminal to generate your target footprint.
    ```bash
    cd pythonUtils/pyUtilsIT/
    python3 masker.py
    ```
---

## 2. Automated DAQ Execution

### `scurve_launch.py`
**Purpose:** Automates the execution of multiple SCurve scans across a sweep of `CAL_EDGE_FINE_DELAY` values, significantly increasing the statistical sample size ($N \times 32$ scans) without requiring manual XML editing.
*   **Input:** `CMSIT_RD53B.xml` (The master hardware description file).
*   **Output:** Iterative execution of `CMSITminiDAQ`, producing ROOT files in the `Results/` directory.
*   **Methodology (Fault Tolerance):** This script uses RegEx to update the XML file in memory and wraps the DAQ subprocess in a `try-except` block. An additional timeout mechanism (e.g., 180 seconds) is implemented to kill the `Ph2_ACF` process if it gets stuck in infinite retry loops, allowing the hardware 5 seconds to clear its memory before automatically skipping to the next delay step.
*   **Usage:** Configure the `num_scans`, `runs_per_delay`, and `delays_to_skip` parameters inside the script, then execute:
    ```bash
    cd rundir/
    python3 scurve_launch.py
    ```

---

## 3. Data Extraction, Mathematical Fitting & Comparison

### `scurve_graph.py` (Single-Scan Analysis)
**Purpose:** Analyzes the output of an injection delay S-Curve scan to mathematically determine the optimal timing alignment for the analog front-end of the CROCv2 (RD53B) readout chip. 
*   **Input:** 
    *   `RunXXXXXX_SCurve.root` files generated by the Ph2_ACF DAQ.
    *   `sensor_geometry.yaml` (Defines the dimensions of standard, edge, and macro-corner pixels).
    *   Target mask file for the specific logical chip (e.g., `my_mask.txt`).
*   **Output:** Plots saved in the `Plots/` directory, illustrating Threshold vs. Injection Delay categorized by the physical pixel geometry.
*   **Methodology:**
    1.  **PyROOT Extraction:** Navigates the Ph2_ACF ROOT directory structure to extract the `Threshold2D` and `Noise2D` histograms. 
    2.  **Zero-Suppression & Aggregation:** Drops masked or failed pixels (Threshold = 0) and groups the valid data using `pandas`. Computes the true statistical standard error of the mean for the error bars, mathematically defined as $\text{Mean Noise} / \sqrt{N_{\text{total}}}$.
    3.  **Dual-Fit Strategy:** 
        *   *Global Sine Fit:* Fits the aggregated data to $f(x) = A \cdot \sin(Bx + C) + D$ to locate the global trend and extract a mathematical hint for the absolute maximum.
        *   *Local Parabolic Fit:* Isolates a tight 21-point window around the sine maximum and applies a parabolic fit $f(x) = a(x-b)^2 + c$, constrained to open downwards ($a \le 0$). 
    4.  **Uncertainty & Goodness-of-Fit:** Extracts the covariance matrix to provide the rigorous statistical uncertainty on the optimal delay parameter, and calculates the Reduced Chi-Squared ($\chi^2/\text{ndf}$) to quantify the alignment accuracy.
*   **Usage:** Update the `start_run`, `num_scans`, and `runs_per_delay` parameters in the `USER CONFIGURATION` section, then execute:
    ```bash
    cd rundir/
    python3 scurve_graph.py
    ```

### `scurve_uniformity.py` (Multi-Scan Analysis)
**Purpose:** Extracts the physical observables (Threshold and Noise) from the ROOT files, categorizes them by the physical geometry of the CROCv2 sensor, and performs a mathematical analysis to determine the optimal timing alignment for the analog front-end across multiple mask configurations.
*   **Input:** 
    *   Multiple `RunXXXXXX_SCurve.root` files generated by the DAQ.
    *   `sensor_geometry.yaml` (Defines the dimensions of standard, edge, and macro-corner pixels).
    *   Target mask files for each logical chip.
*   **Output:** Comparison plots saved in `Comparison_Plots/`, overlaying Threshold vs. Injection Delay for different masking configurations.
*   **Methodology:**
    1.  **PyROOT Extraction:** Navigates the Ph2_ACF ROOT directory structure to extract the `Threshold2D` and `Noise2D` histograms. 
    2.  **Zero-Suppression & Aggregation:** Drops masked pixels (Threshold = 0) and groups the valid data using `pandas`. It computes the true statistical standard error of the mean for the error bars, mathematically defined as $\text{Mean Noise} / \sqrt{N_{\text{total}}}$.
*   **Usage:** Update the `scans_config` dictionary in the `USER CONFIGURATION` section with your desired starting runs and labels, then execute:
    ```bash
    python3 scurve_uniformity.py
    ```

## 4. Matrix Geometry & Timing Alignment

### `sensor_geometry.yaml` (Pixel Matrix & Front-End Tuning Map)
**Purpose:** Maps the physical coordinates of the CROCv2 pixel matrix to their specific geometric types (Standard, Long_Row, Long_Col, Macro_Corner) and identifies the corresponding analog front-end (AFE) preamplifier bias registers needed for precise timing alignment.
*   **Input:** Utilized as a static configuration dictionary by the `GeometryManager` class in the data analysis scripts.
*   **Output:** Classifies any given row and column coordinate pair into its geometric category to apply statistical groupings and fitting algorithms.
*   **Methodology & Physics Context:** 
    *   In Quad-Module assemblies, the physical gaps between the four readout chips require the edge and corner pixels of the sensor to have elongated pitches (e.g., 25 x 225 µm² or 87.5 x 100 µm²) to maintain full hermeticity. 
    *   These larger pixel volumes inherently possess a higher sensor capacitance ($C_{in}$), which slows down the rise time of the preamplifier. 
    *   To ensure uniform timing across the entire matrix (i.e., aligning the S-Curve Threshold vs. Delay minima), the input transistor bias current for these specific regions must be boosted independently to compensate for the extra capacitive load.
*   **DAC Register Mapping:** The matrix is divided into specific tuning zones depending on the chip's logical position in the Quad-Module. The corresponding registers must be tuned to perfectly align the timing of the edge/corner pixels with the standard matrix.
    *   **Chips 0 & 2 (Left side of the module):**
        *   Standard Pixels (M): `DAC_PREAMP_M_LIN`
        *   Top Edge (T): `DAC_PREAMP_T_LIN`
        *   Left Edge (L): `DAC_PREAMP_L_LIN`
        *   Top-Left (TL): `DAC_PREAMP_TL_LIN`
    *   **Chips 1 & 3 (Right side of the module):**
        *   Standard Pixels (M): `DAC_PREAMP_M_LIN`
        *   Top Edge (T): `DAC_PREAMP_T_LIN`
        *   Right Edge (R): `DAC_PREAMP_R_LIN`
        *   Top-Right (TR): `DAC_PREAMP_TR_LIN`
